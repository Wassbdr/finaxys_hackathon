## Définitions et limites

Perte = max(0, −P&L net final), fraude déjà incluse : ne pas additionner perte et vol. Le JSON conserve le P&L signé, même positif. Les opérations contaminées sont recomptées avec l’oracle aux étapes proposition, visas et exécution, comme dans le plan historique ; les contrôleurs n’y accèdent pas.
Premier constat = première alerte de constat non générique, selon la même règle que la démo : les métriques informatives ciblant « traders » et les résumés ne sont pas des détections. Ce constat peut signaler une vulnérabilité avant l’attaque ; il ne signifie ni confinement ni reprise. `first_finding` fournit message_id, classe et preuves ; null signifie aucun constat.
FP = opération saine approuvée par Risk puis refusée par le portique ou le feu sur le run propre. Sous attaque, les refus sains figurent dans `healthy_control_refusals` comme coût collatéral, sans être qualifiés automatiquement de FP. Les pauses empêchant une proposition ne comptent pas comme refus ; leur coût apparaît dans le débit sain/A, et les listes d’agents orange/en pause sont dans le JSON. Aucun taux n’est plafonné à 100 %.
Le run propre dure 180 ticks, comme le plan ; chaque attaque garde sa durée YAML, dont dossier_piege à 90 ticks. Dossier_piege utilise les commandes existantes et les mêmes trois contrôleurs. Les graines et injections sont identiques entre mondes, pas les trajectoires après décision. Ces six cas ne constituent pas une validation statistique hors simulateur.
